Access lists

How is an access list evaluated?

IP rules are checked top to bottom, first match wins. If no rule matches, the request is denied. A list with no IP rules imposes no IP restriction. Basic-auth users are checked separately; Satisfy decides whether a request needs IP or login (any) or IP and login (all).

Allow just GET from everywhere (public read-only)?

One rule: allow · IP/CIDR 0.0.0.0/0 · click the GET chip (and HEAD — browsers and monitors send it). Everything else matches no rule and gets a 403. Add a twin rule with ::/0 if you serve IPv6.

What do the method chips do?

They scope a rule to specific HTTP verbs. None selected = the rule applies to every method. Lit chips = only those verbs. Combine with Satisfy: any + a basic-auth user to get "reads public, writes require login": allow 0.0.0.0/0 with GET, HEAD lit.

Country / dynamic-DNS rules?

A rule's type can be Country (pick from the list; needs a GeoLite2-Country.mmdb in the data dir, whose load status and an IP test live on Settings → Client IP & GeoIP) or Hostname (a dynamic-DNS name, re-resolved periodically) instead of a CIDR.

Proxy hosts vs streams

When do I use a proxy host vs a stream?

Proxy host = HTTP(S) reverse proxy (L7): TLS, HTTP/3, headers, paths, access lists. Use it for websites and APIs. Stream = raw TCP/UDP forward (L4): use it for non-HTTP services (game servers, databases, mail, SSH). Streams see the raw connection, not HTTP.

Reuse an allowlist on a stream?

On a stream, set Source restriction to an existing access list instead of retyping CIDRs — its allow CIDR/host rules become the source filter (only IP rules apply at L4; basic-auth/GeoIP/method rules are ignored there).

Docker labels

How do I route a container by labels?

Run quicgate with QG_DOCKER=1 and the daemon socket mounted read-only (/var/run/docker.sock:ro), then label a container quicgate.enable=true and quicgate.host=app.example.com. It appears on the Docker page. The port is auto-detected when the container exposes exactly one; otherwise set quicgate.port. Set a default base domain (Docker page or QG_DOCKER_DOMAIN) and you can even drop quicgate.host.

A container has a web port and some raw ports?

Add quicgate.streams for the raw ones, e.g. quicgate.streams=25565, 2222:22/tcp, 53/udp ([listen:]container[/proto], proto default tcp). Those become TCP/UDP streams and are excluded from the web-port auto-detection, so the web port still becomes the proxy host. A container can be HTTP-only, streams-only, or both.

Why isn't my labelled container routing?

The Docker page shows every opted-in container with the exact reason: ambiguous ports (set quicgate.port), a name already served by a manual host (manual config always wins), a port not reachable in the current connect-mode, or an unknown access list. Fix the label and it re-derives within a second.

How does quicgate reach the container?

One rule: it connects to the Docker host's address on the container's published port. quicgate.port names the app's port inside the container; quicgate uses its published host mapping (a network_mode: host container is reached at that port directly). So publish the port you want routed. Use Convert to host to turn a derived container into a normal editable host.

Route containers on more than one Docker host?

Yes. In the Docker hosts box (Docker page) give a JSON list of endpoints, each with a name, a connect (a local socket path or tcp://host:2375), and the address where that host's published ports are reachable. Reach a remote daemon through a read-only socket proxy so quicgate never gets write access. Each host's connection state shows at the top of the page.

Certificates & HTTP/3

How do certificates work?

Set a host's cert mode to Automatic for Let's Encrypt (HTTP-01, or DNS-01 for wildcards once a DNS provider is configured in Settings), Custom to use an uploaded cert, or None for plain HTTP. Watch issuance on the Certificates page.

HTTP/3 isn't working from outside?

HTTP/3 needs UDP 443 forwarded to this host (TCP 443 alone isn't enough). Browsers upgrade via Alt-Svc and cache the hint ~30 days; a host's per-host HTTP/3 toggle sends Alt-Svc: clear to drop it. Let QG_UPNP=1 open the ports, or forward them manually.

Security & ops

Is it safe to expose the admin UI?

No. Never expose the admin port (81) to the internet. Put it behind quicgate itself with an access list, a VPN, or a firewall rule — treat it like any other private service. Change the default admin@example.com/changeme on first run and enable 2FA (account menu → Account & security).

How do I script quicgate / use the API?

Create a bearer token under your account menu → API tokens and send Authorization: Bearer <token>. Everything the UI does is a REST call — see the interactive API docs. POST /api/import does idempotent bulk config-as-code.

SSO in front of a host?

Two ways. Built-in OIDC (no extra service): add your IdP under Access control → Identity providers, then enable OIDC SSO on the host's Security tab. quicgate runs the OpenID Connect login itself, keeps a signed per-host session, checks the allowed emails/domains/groups you set, and can pass the identity upstream as Remote-User / Remote-Email / Remote-Groups (spoofed inbound copies are always stripped). Register the redirect URI https://<host>/.qg/oidc/callback at the IdP; sign out at /.qg/oidc/logout. Or use Forward authentication against an Authelia / Authentik verify endpoint if you already run one.

Can one path be public while the rest of the host needs auth?

Yes. On a proxy host, Security → Path authentication takes ordered per-URL rules: a path, prefix or exact match, and what gates it (Public, a specific access list, the host's forward auth, or the host's OIDC SSO). The longest matching path wins, and any path matching no rule keeps the host's own access list and forward auth. Use it for a licensing callback, a webhook receiver or a health probe that cannot log in. Optionally scope a rule to certain verbs, e.g. public GET but gated POST. Rate limits, bad-bot and exploit filters stay host-wide and still apply to public paths.

Backup, metrics, logs?

The Logs page is the access-log viewer (unmatched traffic, all traffic or one host; a host's Logs button opens it for that host). Settings → Backup & restore has one-click backup and restore. Prometheus scrape at /metrics (needs a bearer token).

Found a bug or have an idea? Open an issue. Security problems: see the repo's security policy (don't use public issues).
